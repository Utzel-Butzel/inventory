# Brother PT-P710BT with QZ Tray

Inventory can print labels directly from the desktop browser through QZ Tray
and a local USB print queue. The printer does not need P-touch Editor for this
workflow. The web server can run remotely; QZ Tray and the printer must be on
the computer running the browser.

## macOS setup

1. Install [QZ Tray](https://qz.io/download/) from the official installer and
   start it. Allow its macOS certificate installation so HTTPS pages can connect.
2. Connect and switch on the PT-P710BT. Find its USB URI with
   `/usr/sbin/lpinfo -v` (look for `usb://Brother/PT-P710BT?serial=...`).
3. Create a dedicated queue, replacing the URI with the actual device URI:

   ```sh
   /usr/sbin/lpadmin -p Brother_PT_P710BT_RAW -E \
     -v 'usb://Brother/PT-P710BT?serial=YOUR_SERIAL' \
     -m 'drv:///sample.drv/generic.ppd' \
     -D 'Brother PT-P710BT (Inventory / QZ)'
   ```

   Recent macOS versions reject a queue created with `-m raw`. The generic PPD
   permits queue creation; Inventory uses QZ's `forceRaw: true` so CUPS passes
   Brother raster commands unchanged, bypassing that PPD. This dedicated queue
   is for Inventory raster jobs, not ordinary browser PDF/PostScript jobs.

4. In **Labels**, select **Brother PT-P710BT · USB / QZ Tray**, select the
   actual loaded tape width, and click **Connect to QZ Tray**. Approve the QZ
   access request. Select the Inventory / QZ printer if multiple queues exist.
5. Select an inventory item and the included P-touch template, then print one
   label. Verify its appearance and scan the QR code before printing a batch.

The destination is remembered in this browser. Tape width is selected manually.
The printer rejects a job if the requested laminated tape width does not match.
Printer status and tape width are not read through QZ's USB API; the macOS
QZ Tray 2.3.0 USB native library failed during testing, while the CUPS queue
printed successfully.

## Layout and quality

Labels render at 180 × 360 dpi: 180 across the tape and 360 along the feed.
The 24 mm tape has a maximum printable height of 128 dots (about 18.1 mm).
The included white 24 mm tape template uses 80 × 18 mm of printed content,
an 18 mm QR code, Barlow Semi Condensed title/subtitle and a product photo.
It is built in, so it is also available on a fresh production deployment.
Smaller tapes use the compact 56 mm text template and have
smaller printable areas. The printer adds a nominal 2 mm margin at each end,
cuts between labels and feeds/cuts after the final label of a series; cutter
mechanics add leading tape waste once at the start of a job.

Inventory renders the complete layout to monochrome raster and checks QR
readability at the physical label proportions before submitting any jobs.
Product photos receive a moderate shadow lift (gamma 0.8), 1.25× contrast and local sharpening before
ordered halftoning to preserve gray detail on the monochrome
printer. Only the product-photo area is halftoned; text and QR codes retain crisp
black/white edges. Pairing feed dots keeps the halftone cells physically square
at 180 × 360 dpi.
Use larger QR codes and sufficient contrast, especially on narrow tapes.
Browser printing remains available for other printers and label formats.

For a full-height QR on white 24 mm tape, an 18 mm symbol can use the physical
~3 mm unprinted top/bottom tape edges as its quiet zone. Reserve at least four
modules of blank space left/right too (2.2 mm for an 18 mm, 33-module symbol).
The built-in photo template reserves 2.5 mm left and 3.5 mm before the title, with
zero additional quiet-zone modules inside the QR element. This layout is meant
for white 24 mm tape; other media and ordinary browser output need their own
adequate quiet zones. QR preflight includes the physical tape height.

The small blank offcut before each independent job is the printer's required
leading tape, approximately 25 mm according to Brother, not an extra blank
label generated by the app. On 24 mm tape it looks almost square. Consecutive
pages reduce this to the beginning of a series. Inventory now sends a complete
series as one raw queue job: one initialization, subsequent-page flags,
chain mode and FF for intermediate pages, then no-chain mode and Control-Z
for the final page. This finishes the series without leaving the last label
inside the printer.
See [Brother's explanation for the PT-P710BT](https://support.brother.com/g/b/sp/faqend.aspx?c=hk&faqid=faqp00001472_003&lang=en&prod=p710bteas).

A batch is limited to 100 labels and 4 MB of raw data. Submission
success means the local queue accepted the data; it does not prove that the
printer physically finished. After an error, inspect the queue and output before
retrying to avoid duplicate labels. Do not automatically retry print requests.

## Prepare a print list

Select entries, copies and a template, then choose **Prepare labels**. This does
not connect to QZ or print anything. Image loading, QR readability and tape fit
are checked first; the finished raster and preview are captured together. The
current selection clears so additional entries or another template can be added.
Changing templates later cannot alter already prepared labels.

The list shows each label, its template and a preview, with individual removal
and clear-all actions. Every label must use the same tape width, but label
lengths and layouts may differ. Connect QZ, select the matching loaded tape and
choose **Print as a series**. The list clears only after QZ accepts the single
job; on failure it stays available for inspection. Do not retry before checking
the physical output, because acceptance is not a device completion signal.

Prepared labels and destination preferences are saved on the server for the
current user and organization through `/api/v1/label-workspace`. Reloading or
returning to Labels restores the list. Wait for a successful save; a failed
preference save is shown in the interface. Queue edits include a revision so a
stale browser cannot overwrite a newer list (HTTP 409). The list supports up to
100 prepared labels and a 24 MiB workspace request, in addition to the 4 MB RAW
print-job limit. Direct printing of multiple selected labels uses the same
series encoding. Browser-dialog printing remains available.

The shared Office destination uses the same prepared labels. See
[Windows print-agent setup](../scripts/print-agent/README.md). The browser submits
a job over HTTPS; the printer PC pulls it without an inbound firewall rule.
Printer and job administration requires a browser session, not a normal API token.

## QZ approval prompts and optional signing

Without signing, QZ asks for approval when connecting or printing. This mode is
usable without a certificate purchase, but it is not silent printing.

To use a QZ-trusted certificate, configure both `QZ_CERTIFICATE_PATH` and
`QZ_PRIVATE_KEY_PATH` on the Inventory server. Keep the private key outside the
repository and web root, with read access restricted to the app process. Never
put it in a `NEXT_PUBLIC_*` variable or browser bundle. Use QZ's supported
[certificate and signing workflow](https://qz.io/docs/signing); a locally created
demo certificate is suitable for development only and must be trusted on each
test computer.

For container hosts without secret file mounts, set `QZ_CERTIFICATE_BASE64`
and `QZ_PRIVATE_KEY_BASE64` to base64-encoded PEM contents in the deployment
environment. Base64 is only transport encoding, not encryption; the private
key remains a secret. File paths take precedence when both are configured.
QZ also supports an organization-owned signing root. Trust it explicitly in
QZ on each printing computer and allow only the matching signing certificate.
This does not require installing a general-purpose browser or macOS root CA.

The authenticated endpoints `/api/v1/labels/qz-certificate` and
`/api/v1/labels/qz-sign` require `labels.read`. Signing is limited to recent
printer-discovery requests and raw, single-copy PT-P710BT queue jobs. File,
network, serial and direct USB commands are not signed. Missing signing
configuration returns 503 and the browser falls back to QZ approval prompts.

## Verification

Run `npm run test:labels`, `npm run test:i18n` and `npm run typecheck`.
Protocol tests cover tape dimensions, orientation, alpha compositing,
180 × 360 dpi flags/margins, multi-page sequencing and final feed/cut,
mixed-media and size rejection, and signing request restrictions. Hardware checks
remain necessary after changes to the raster protocol or printer setup.

Protocol reference: [Brother raster command reference, v1.02](https://download.brother.com/welcome/docp100064/cv_pte550wp750wp710bt_eng_raster_102.pdf).

## Subtitle and print-only text

Each resource has an optional `subtitle` (up to 240 characters), editable in the resource form. Apply migration `0069_resource_subtitle.sql` before deploying the updated application; existing resources receive an empty subtitle.

The label designer exposes Subtitle as an independent text element with position, font size and overflow settings. Existing saved templates keep their layout until Subtitle is added. The built-in P-touch preset includes it.

In the label selection, Title and Subtitle can be overridden for each resource or stock-unit target. These overrides affect preview, browser printing and prepared P-touch jobs only; they never update the resource. “Use item text” restores the selected article's text. Copies share the selection's overrides.

Prepared labels retain their resource and template snapshot. “Edit label text” opens a preview and regenerates the stored raster when applied, including the QR validation; cancelling or a rendering error preserves the prior label. The updated label is saved back to the personal print list.


## Individual units and current layout controls

Select a resource or one of its serialized units. A unit label uses the unit code
and a short resource URL with a `unit` query parameter derived from its UUID.
Editing the human-readable code does not change that URL. Title and subtitle
overrides still affect only the printed label.

Templates support up to 32 uniquely identified elements, including repeated text
or image elements, rich text, subtitle, custom images, fonts, alignment, tracking,
line height, image cropping and an inverted output option. A visible image must
not overlap a visible QR code. A single text element can use `autoWidth` to adjust
the physical label length to its rendered content; check the preview and media fit
before printing. The same computed dimensions are used for preview, browser and
P-touch output. Drafts can be test-printed before saving or saved as a new template.

Each selected target has an explicit copy count. Copies count toward the 100-label
series limit. Keep one tape width per series; lengths and layouts may differ.
